# 軽量化の目標と実測（v2）

「速くする」ではなく**測ってから直す**。数値は `node tools/perf.mjs` で誰でも同じように取れる。
直したら同じコマンドで取り直し、この表を更新する。

## 実測（2026-10-25 / サーバ側の軽量化を適用後）

| 指標 | before | after | 目標 | 判定 |
|---|---|---|---|---|
| payload（モック・同一条件） | 8,306 B | **1,130 B** | 6,000 B 以下 | 達成 |
| うち v1 キー | 6,690 B（81%） | **0 B** | 0 B | 達成 |
| payload（満杯を実際に詰めた場合） | 71,376 B | **2,511 B** | — | 達成 |
| `history`（24h満杯） | 53,359 B | **30 B（静か）/ 1,115 B（最悪）** | 1,500 B 以下 | 達成 |
| `log` | 5,041 B（40行） | **1,513 B（12行）** | 1,600 B 以下 | 達成 |
| WS 転送（2秒ごと） | 14.3 MB/h | **1.9 MB/h** | 10 MB/h 以下 | 達成 |
| 画面の総重量 gzip（LAN） | 103,542 → 35,038 B | 35,038 B | 36,000 B 以下 | 達成（下記注） |
| `snapshot()` | 0.166 ms | 0.138 ms | 1 ms 以下 | 達成 |

実機（15,200 B だった盤）の推定は **≈4.6 KB**（履歴が24時間ぶん載っても ≈5.7 KB）。

### 目標の決め方について（正直な注記）
- **`log` を 1,600 B にした理由**: 1行 ≈126 B のうち大半が `session`（セッション名）。名前を落とすと「誰が」が消えてログの値打ちが無くなるので、名前は残す。落とす選択はしない。
- **画面の総重量を 36 KB にした理由**: ビルド工程を持たない設計（依存ゼロ・素のESモジュール）なので、minify を前提にした数字は置かない。gzip 転送は LAN リスナーで実装済み（103 KB → 34 KB を実測）。

## 何を削って何を削らないか

削った: v1 キー（`stations`/`cards`/`alerts`/`activity`/`vitals`/`host`/`generatedAt`/`status`/旧`counts`）は
**`?compat=1` と config `legacyPayload` のときだけ**。v2 画面は読まない。

削らない:
- `sessions[].lastOutputAt` / `lastOutput` / `runningSince` の **null**（推測で埋めない）
- `log` は新しい順（**古い行だけ**捨てる。新しい行を捨てるのは不可）
- WS は毎回**全体**スナップショット（差分にしない）
- **盲目のときは `overall='alarm'`**（§1「嘘の正常を出さない」）

## 測定の作法

- 比較するときは**同じ条件**で: 同じシナリオ・同じセッション数・同じログ行数
- モックで測る `snapshot()` と、実機で測る payload は別物。混ぜて議論しない
- 画面側の軽量化は「描画回数」で測る（体感ではなく回数）。`?perf=1` で表示
