# アンドン v2 契約（サーバ ⇄ クライアント）

この文書は実装の境界線。**サーバ側とクライアント側はこの形だけを頼りに並行実装する。**
ここに書いていない形を勝手に増やさない。増やすときはこのファイルを先に直す。

仕様書 = 「DSH アンドン 改善仕様書（完全版）ドラフト1」。節番号はそれを指す。

---

## 1. 状態（§2）

状態は5つ。サーバは `offline` 以外の4つを判定し、`offline` だけクライアントが判定する
（§7「状態の判定ロジックはサーバ側に1つだけ。通信断だけクライアントでも判定する」）。

| 値 | 記号 | 意味 |
|---|---|---|
| `normal` | ○ | 他に該当なし |
| `watch` | △ | 注意 |
| `needs-you` | ◆ | 人が今動くべき |
| `alarm` | ✕ | 異常 |
| `offline` | ？ | 通信断（クライアントのみ） |

優先順（worst-wins）: `offline` > `alarm` > `needs-you` > `watch` > `normal`。

### 判定規則（サーバ側、しきい値は設定で変更可能）

`sessions[]` の各セッションを次の順で1つに決める（上が優先）:

1. `alarm` — 承認待ち/入力待ちが `needsYouStaleMs` 以上放置、または `contextPct >= contextAlarmPct`、
   またはセッションがエラー/停止で終わっている
2. `needs-you` — 承認待ち・入力待ちがある
3. `watch` — `status === 'running'` かつ `lastOutputAt` が `noOutputMs` 以上前、
   または `contextPct >= contextWarnPct`
4. `normal`

`overall` = 全セッションの最悪値。セッションが0件なら `normal`。

### しきい値の既定値（`config.rules` で上書き可）

```jsonc
{
  "noOutputMs": 300000,       // 5分: 実行中なのに出力が無い
  "contextWarnPct": 80,       // 注意
  "contextAlarmPct": 90,      // 異常
  "needsYouStaleMs": 300000,  // 5分: 要対応の放置で異常へ昇格
  "offlineMs": 6000,          // クライアント側: 最終受信から通信断
  "heartbeatMs": 2000         // スナップショット送信間隔
}
```

**仕様書 §2 からの意図的な変更 1点**: 「注意: 最終受信から3秒超」は削除した。
送信間隔が2秒なので正常時でも3秒を超え、橙が常時点滅する。受信の遅れは
`offline`（6秒）で表現する。§11-1/2 の受け入れ条件はこの定義で満たす。

## 2. ペイロード（§7）

### スナップショット（差分ではなく毎回全体）

```jsonc
{
  "v": 2,
  "serverTime": 1760000000000,   // epoch ms。経過時間はすべてこれ基準
  "seq": 42,                     // 2秒ごとに +1。飛んだ/戻ったらクライアントは再取得
  "build": "and-on-v2",          // 変わったらクライアントは自動リロード（§7）
  "overall": "normal",           // offline は入らない（クライアントが付ける）
  "reason": "承認待ち 1件",       // overall の理由を1行。無ければ ""
  "counts": {
    "needsYou": 0,               // 要対応セッション数
    "running": 3,                // 実行中セッション数
    "contextMax": 82             // 全セッションの最大 contextPct（0..100 の整数）
  },
  "sessions": [
    {
      "id": "session-...",
      "name": "dsh-andon を完成させる",   // 取得できなければ id の短縮形
      "status": "running",              // "running" | "idle" | "error" | "stopped"
      "state": "normal",                // 上記4値（offline は来ない）
      "reason": "",                     // "承認待ち" / "無反応 6分" / "コンテキスト 92%"
      "since": 1760000000000,           // **この state になった時刻**（経過表示の基準）
      "runningSince": 1760000000000,    // **実行が始まった時刻**。不明なら null
      "lastOutputAt": 1760000000000,    // 最終出力時刻。**不明なら null**（推測禁止）
      "lastOutput": "README を直す",     // 最終出力の1行（40文字以内）。不明なら null
      "contextPct": 82                  // 0..100。不明なら null
    }
  ],
  "log": [
    {
      "at": 1760000000000,
      "session": "dsh-andon を完成させる",  // セッション名。無関係なら ""
      "severity": "ok",                    // "ok" | "warn" | "alert"
      "text": "タスク開始: README を直す"   // **人間の言葉**（内部イベント名を出さない）
    }
  ],
  "history": [                             // §7 履歴帯。P2。無くてもクライアントは動くこと
    { "at": 1760000000000, "state": "normal" }
  ]
}
```

- `lastOutputAt` / `lastOutput` / `contextPct` / `runningSince` が **null のとき、クライアントは `取得不可` と表示する**。
  0 や現在時刻で埋めるのは禁止（§0「推測値は出さない」）。
- **`since` と `runningSince` を取り違えない。** `since` は「この状態になってからの経過」、
  `runningSince` は「実行が始まってからの経過」。§3 の一覧に出る「実行経過」は
  `runningSince` から計算する（null なら `取得不可`）。`since` を実行経過として出すのは
  「動いていないセッションが動いているように見える」ので禁止。
- `log` は新しい順。最大 40 行。クライアントは10行以上見せる。
- 時刻はすべて epoch ms。ISO 文字列にしない。

### 転送路

| 経路 | 用途 |
|---|---|
| `GET /api/andon/state` | 1回だけ同じスナップショットを返す（既存互換・デバッグ・プレビュー用） |
| WS `/api/andon/stream` | upgrade。接続直後に1通、以後 `heartbeatMs` ごとに全スナップショット |
| `POST /api/andon/ack` | 確認（ACK）。本文 `{ "seq": 42, "overall": "alarm", "device": "fire-tab" }` → 200。ログに1行残す |

- WS は `ctx.webServer.registerUpgrade({ path, handler })` で登録する。**LAN リスナー側にも同じパスを張る**。
- WS が使えない環境（古いブラウザ等）でも `GET /api/andon/state` で動くこと。クライアントは
  WS 失敗時にポーリングへ落ちる。
- ACK は**状態を消さない**。止めるのは点滅と音だけ（§6）。

## 3. 画面（§3）

- 正常・注意 = **暗背景**（`#0F1115` 前後）。全面を緑にしない。
- 要対応 = 橙の全画面、異常 = 赤の全画面＋点滅、通信断 = 灰の全画面。
- ヘッダ帯は指標3つだけ（要対応 / 実行中 / コンテキスト最大）。8項目は出さない。
- 正常時はセッション一覧（1行1セッション、最低12行、あふれは「他N件」）。
- 要対応・異常は対象セッションをカードで最大3枚（4件目以降は「他N件」）。
- 通信断は「通信断」「最終受信 ○分○秒前」「再接続中（試行N回目）」以外を**出さない**。

## 4. 消すもの（§9）

左パネルの1〜8番号 / 行頭の緑ドット / `LIVE` / `·` 区切りと字間を広げた小ラベル /
要約文（`異常なし · 実行中 5 · セッション 6`）/ 巨大な `0 件` / 秒表示の大時計 /
左パネルだけの大きい角丸 / 略語（サブ・目標・文脈・異常計）/ 内部イベント名のログ /
正常時の全面緑。

## 5. 守ること（実装共通）

- **依存を増やさない**（Node 標準のみ、npm 追加なし、ビルド工程なし）。
- クライアント JS は **ES2015 まで**（Fire タブの Silk 対策）。`?.` `??` `async/await`
  `padStart` `Object.entries` `**` 数値セパレータ禁止。テストが検査している。
- 色は4色のみ（緑・橙・赤・灰）。角丸なし。罫線1px。余白は8pxの倍数。
  数字は `font-variant-numeric: tabular-nums`。`letter-spacing` は 0〜-0.02em。
- 状態は「色＋記号＋文字」の3つで必ず表す。`prefers-reduced-motion` では点滅せず太枠。
- **新しい CSS ファイルを作らない**（新規ファイル＝新ルート＝ホスト再起動が要る）。
  ページ固有の見た目はそのページの `<style>` に書く。
