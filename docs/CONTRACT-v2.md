# アンドン v2 契約（サーバ ⇄ クライアント）

この文書は実装の境界線。**サーバ側とクライアント側はこの形だけを頼りに並行実装する。**
ここに書いていない形を勝手に増やさない。増やすときはこのファイルを先に直す。

仕様書 = 「DSH アンドン 改善仕様書（完全版）ドラフト1」。節番号はそれを指す。

---

## 1. 状態（§2）

状態は5つ。サーバは `offline` 以外の4つを判定し、`offline` だけクライアントが判定する
（§7「状態の判定ロジックはサーバ側に1つだけ。通信断だけクライアントでも判定する」）。

| 値 | 記号 | 意味 |
|---|---|---|
| `normal` | ○ | 他に該当なし |
| `watch` | △ | 注意 |
| `needs-you` | ◆ | 人が今動くべき |
| `alarm` | ✕ | 異常 |
| `offline` | ？ | 通信断（クライアントのみ） |

優先順（worst-wins）: `offline` > `alarm` > `needs-you` > `watch` > `normal`。

### 判定規則（サーバ側、しきい値は設定で変更可能）

`sessions[]` の各セッションを次の順で1つに決める（上が優先）:

1. `alarm` — 承認待ち/入力待ちが `needsYouStaleMs` 以上放置、または `contextPct >= contextAlarmPct`、
   またはセッションがエラー/停止で終わっている
2. `needs-you` — 承認待ち・入力待ちがある
3. `watch` — `status === 'running'` かつ `lastOutputAt` が `noOutputMs` 以上前、
   または `contextPct >= contextWarnPct`
4. `normal`

`overall` = 全セッションの最悪値。セッションが0件なら `normal`。

### しきい値の既定値（`config.rules` で上書き可）

```jsonc
{
  "noOutputMs": 300000,       // 5分: 実行中なのに出力が無い
  "contextWarnPct": 80,       // 注意
  "contextAlarmPct": 90,      // 異常
  "needsYouStaleMs": 300000,  // 5分: 要対応の放置で異常へ昇格
  "offlineMs": 6000,          // クライアント側: 最終受信から通信断
  "heartbeatMs": 2000         // スナップショット送信間隔
}
```

**仕様書 §2 からの意図的な変更 1点**: 「注意: 最終受信から3秒超」は削除した。
送信間隔が2秒なので正常時でも3秒を超え、橙が常時点滅する。受信の遅れは
`offline`（6秒）で表現する。§11-1/2 の受け入れ条件はこの定義で満たす。

## 2. ペイロード（§7）

> **v2.1 変更（転送の軽量化 / サーバ担当）** — `build` が `and-on-v2.1` に変わった。
> 開いている盤は自動リロードされる（§7）。**クライアントが対応する点**:
> 1. **`history` の形が変わった（要対応）**: `[{ at, state }]` → `[fromMs, stepMs, codes]`。
>    今のままだと履歴帯が「記録なし」の灰色になる（落ちはしない）。
> 2. `log` は**最大12行**だけ届く（契約の上限は40行のまま。10行表示なので12行で足りる）。
> 3. v1 キー（`schema` / `stations` / `cards` / `alerts` / `activity` / `vitals` /
>    `host` / `generatedAt` / `status` / v1 の `counts`）は**既定では届かない**。
>    `GET /api/andon/state?compat=1`（または plugin config `legacyPayload: true`）でのみ届く。
> 4. `notes: string[]` を**追加**（通常は空配列。収集の不調を1行で説明する）。

### スナップショット（差分ではなく毎回全体）

```jsonc
{
  "v": 2,
  "serverTime": 1760000000000,   // epoch ms。経過時間はすべてこれ基準
  "seq": 42,                     // 2秒ごとに +1。飛んだ/戻ったらクライアントは再取得
  "build": "and-on-v2.1",        // 変わったらクライアントは自動リロード（§7）
  "overall": "normal",           // offline は入らない（クライアントが付ける）
  "reason": "承認待ち 1件",       // overall の理由を1行。無ければ ""
  "counts": {
    "needsYou": 0,               // 要対応セッション数
    "running": 3,                // 実行中セッション数
    "contextMax": 82,            // 全セッションの最大 contextPct（0..100 の整数）
    // 以下はレール8局を画面側で組み立てるための数字（合計 ~100B）。
    // これがあるおかげで画面は `?compat=1`（v1 キー入り・約12KB）を読まなくて済む。
    "sessions": 8,               // 生存セッション数
    "jobsRunning": 1,            // 稼働中ジョブ
    "jobsFailed": 0,             // 失敗ジョブ（2時間窓）
    "subagents": 0,              // 稼働中サブエージェント
    "goalsBlocked": 0,           // 遮断された目標
    "goalsPaused": 0,            // 休止中の目標
    "errors": 0                  // 異常計（失敗ジョブ＋診断＋起動失敗）
  },
  "sessions": [
    {
      "id": "session-...",
      "name": "dsh-andon を完成させる",   // 取得できなければ id の短縮形
      "status": "running",              // "running" | "idle" | "error" | "stopped"
      "state": "normal",                // 上記4値（offline は来ない）
      "reason": "",                     // "承認待ち" / "無反応 6分" / "コンテキスト 92%"
      "since": 1760000000000,           // **この state になった時刻**（経過表示の基準）
      "runningSince": 1760000000000,    // **実行が始まった時刻**。不明なら null
      "lastOutputAt": 1760000000000,    // 最終出力時刻。**不明なら null**（推測禁止）
      "lastOutput": "README を直す",     // 最終出力の1行（40文字以内）。不明なら null
      "contextPct": 82                  // 0..100。不明なら null
    }
  ],
  "log": [                               // **最大12行**。古い行から捨てる（新しい行は捨てない）
    {
      "at": 1760000000000,
      "session": "dsh-andon を完成させる",  // セッション名。無関係なら ""
      "severity": "ok",                    // "ok" | "warn" | "alert"
      "text": "タスク開始: README を直す"   // **人間の言葉**（内部イベント名を出さない）
    }
  ],
  "history": [                           // §7 履歴帯。無くてもクライアントは動くこと
    1761555000000,                       // [0] fromMs: 先頭の分の開始時刻（epoch ms）
    60000,                               // [1] stepMs: 1点あたりの間隔（= 1分）
    "n720a3"                             // [2] codes: ランレングス（下記）
  ],
  "notes": []                            // 収集の不調の説明。通常は空配列。**空でも必ず入る**
}
```

#### `history[2]` の `codes`（v2.1）

`<コード><分>` を連結したランレングス文字列。分を省いたら1分。

| コード | 意味 |
|---|---|
| `n` | normal（○） |
| `w` | watch（△） |
| `y` | needs-you（◆） |
| `a` | alarm（✕） |
| `-` | 記録なし（その分は誰も報告していない。**`n` とは違う**） |

- 点 `i` は `[fromMs + i*stepMs, fromMs + (i+1)*stepMs)` を覆う。**古い順**（左から右へ描ける）。
- 例: `[t, 60000, "n720a3"]` = 12時間 正常、そのあと3分 異常。
- 1点1文字ではないので**必ず展開する**（`a1y1a1…` は1分ごとに反転した日）。
- 24時間ぶんでも 1,500 B 以下。極端に状態が動いた日は**古い側が落ちる**。
  `fromMs` より前は「記録なし」として描く（新しい側は落とさない）。
- `[]`（空配列）は履歴なし。

#### `notes`（v2.1）

- `notes[]` が空でなければ、その内容を盤に出す（常設でなくてよい。下部に1行など）。
- 収集が致命的に失敗したとき（セッション一覧・エージェント一覧が取れない）は
  `overall` が **`alarm`**、`reason` が「状態を収集できません」になる。
  **このとき盤を緑にしてはいけない**（仕様書 §1「嘘の正常を出さない」）。

- `lastOutputAt` / `lastOutput` / `contextPct` / `runningSince` が **null のとき、クライアントは `取得不可` と表示する**。
  0 や現在時刻で埋めるのは禁止（§0「推測値は出さない」）。
- **`since` と `runningSince` を取り違えない。** `since` は「この状態になってからの経過」、
  `runningSince` は「実行が始まってからの経過」。§3 の一覧に出る「実行経過」は
  `runningSince` から計算する（null なら `取得不可`）。`since` を実行経過として出すのは
  「動いていないセッションが動いているように見える」ので禁止。
- `log` は新しい順。**転送は最大12行**（契約の上限は40行。UI が10行表示なので12行で足りる。
  古い行から捨てる。新しい行を捨ててはいけない）。クライアントは10行以上見せる。
- 時刻はすべて epoch ms。ISO 文字列にしない。
- **`ask`（任意・通常は null）**: 盤から答えられる質問。いまは承認のみ。
  ```jsonc
  "ask": { "id": "ask_x1", "tool": "bash", "reason": "pnpm install を実行します",
           "session": "…", "since": 1760000000000, "deadline": 1760000010000 }
  ```
  - `POST /api/andon/answer` に `{ "id": "ask_x1", "outcome": "allowed-once" | "rejected" }` を
    送ると決着する。`allowed-once` が唯一の許可。
  - **既定では無効**（`rules.boardAnswerMs` 未設定＝0）。有効にすると承認のたびに盤の
    返事を最大その時間だけ待ち、答えなければ DSH 側の UI に渡す（今までの答え方は残る）。
    **盤に「許可/拒否」のボタンができてから有効にすること。** ボタンが無い状態で有効に
    すると、承認が毎回その時間だけ止まり、PC が固まったように見える（実際に起きた）。
  - 盤が「見ている」かの判定は、ポーリングか WS で最後に来た時刻から 15 秒。
- **§11-7（時計補正）を検証するときの罠**: `serverTime` だけを +5分ずらすと、
  ペイロード内の `since` / `lastOutputAt` と矛盾した「別の壊れ方」を作ってしまう
  （実装を疑う前に、テストが正しいか疑うこと）。正しい再現は
  **サーバが返す時刻を全部同じだけずらす**こと。端末時計がずれている状況に相当し、
  そのとき経過表示が変わらなければ補正が効いている。
  実測 2026-10-24: ずれなし 48分53秒 / +5分 48分51秒（差は撮影間隔のみ）で合格。

### 転送路

| 経路 | 用途 |
|---|---|
| `GET /api/andon/state` | 1回だけ同じスナップショットを返す（既存互換・デバッグ・プレビュー用）。既定は軽い形 |
| `GET /api/andon/state?compat=1` | 同じスナップショット＋**v1 キー**（移行期の旧画面・`tools/shots.mjs` 用） |
| WS `/api/andon/stream` | upgrade。接続直後に1通、以後 `heartbeatMs` ごとに全スナップショット（v1 キーなし） |
| `POST /api/andon/ack` | 確認（ACK）。本文 `{ "seq": 42, "overall": "alarm", "device": "fire-tab" }` → 200。ログに1行残す |

- **`GET /api/andon/state` と WS は同じ1つのスナップショットを返す**（`compat` の有無だけが違う）。
  軽い形に無いキーは「無い」が正であり、旧画面は `?compat=1` を使う。
- LAN リスナー（`lan.enabled`）は HTML/JS/CSS を `accept-encoding: gzip` のとき gzip で返す
  （`content-encoding` と `vary` を付け、`content-length` は実際のバイト数）。
  ハーネス経路（`ctx.webServer`）は圧縮しない（ホスト側の転送に任せる）。

- WS は `ctx.webServer.registerUpgrade({ path, handler })` で登録する。**LAN リスナー側にも同じパスを張る**。
- WS が使えない環境（古いブラウザ等）でも `GET /api/andon/state` で動くこと。クライアントは
  WS 失敗時にポーリングへ落ちる。
- ACK は**状態を消さない**。止めるのは点滅と音だけ（§6）。

## 3. 画面（§3）

- 正常・注意 = **暗背景**（`#0F1115` 前後）。全面を緑にしない。
- 要対応 = 橙の全画面、異常 = 赤の全画面＋点滅、通信断 = 灰の全画面。
- ヘッダ帯（レール）は指標4つだけ（要対応 / 作業中 / 記憶 / 異常）。8項目は出さない。
- 正常時はセッション一覧（1行1セッション、最低12行、あふれは「他N件」）。
- 要対応・異常は対象セッションをカードで最大3枚（4件目以降は「他N件」）。
- 通信断は「通信断」「最終受信 ○分○秒前」「再接続中（試行N回目）」以外を**出さない**。

## 4. 消すもの（§9）

左パネルの1〜8番号 / 行頭の緑ドット / `LIVE` / `·` 区切りと字間を広げた小ラベル /
要約文（`異常なし · 実行中 5 · セッション 6`）/ 巨大な `0 件` / 秒表示の大時計 /
左パネルだけの大きい角丸 / 略語（サブ・目標・文脈・異常計）/ 内部イベント名のログ /
正常時の全面緑。

## 5. 守ること（実装共通）

- **依存を増やさない**（Node 標準のみ、npm 追加なし、ビルド工程なし）。
- クライアント JS は **ES2015 まで**（Fire タブの Silk 対策）。`?.` `??` `async/await`
  `padStart` `Object.entries` `**` 数値セパレータ禁止。テストが検査している。
- 色は4色のみ（緑・橙・赤・灰）。角丸なし。罫線1px。余白は8pxの倍数。
  数字は `font-variant-numeric: tabular-nums`。`letter-spacing` は 0〜-0.02em。
- 状態は「色＋記号＋文字」の3つで必ず表す。`prefers-reduced-motion` では点滅せず太枠。
- **新しい CSS ファイルを作らない**（新規ファイル＝新ルート＝ホスト再起動が要る）。
  ページ固有の見た目はそのページの `<style>` に書く。
